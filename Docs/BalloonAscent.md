# Balloon ascent scene

Assets/Scenes/BalloonAscent.unity uses the actual Player and Balloon prefab instances with their ordinary movement, input, rope physics and animation components enabled. Player Rope Interaction > Initial Rope references the balloon rope; Initial Grip Fraction = 1 starts grabbed at its end. Empty Initial Rope leaves existing scenes unchanged. The ordinary rope attachment path is shared with manual grabbing, and initial attachment runs in Start after rope chains initialize in Awake.

The balloon uses BalloonLift and PropsMotion. Lift Capacity = 3 supports the mouse and produces upward acceleration. Adjust the balloon body Air Drag, Max Speed and Balloon Lift > Lift Acceleration / Lift Capacity to tune ascent. The rig parent only organizes the objects; it does not move them. Hunger and oxygen are disabled on the cinematic player instance. The camera uses the existing PlatformCameraController and a 32 PPU, 320x180 PixelPerfectCamera. The Hanging animation follows the real Attached state through PlayerAnimation.

The black shaft reaches Tunnel Exit at Y=40, with dark wall panels, overhead 2D spotlight and ambient light. Shaft walls have colliders. Exit Whiteout is a camera-child sprite using Assets/Materials/BalloonExitFlash.mat and HeightWhiteout.shader. It fades from transparent to full-screen white as the camera crosses Flash Start Height and Flash End Height. The end height is set before the balloon reaches the tunnel opening. This is a height-driven visual effect; no dedicated ascent controller, forced animation or scripted player translation is used. Moving the exit requires adjusting those material heights and the wall geometry.

Tools > Gameplay > Create Balloon Ascent Scene creates a new scene without overwriting an existing one. Tools > Gameplay > Use Real Player In Balloon Ascent wires or restores the physical version and removes the obsolete cinematic controller and overlay. A scene already open remains dirty without automatic saving; a scene opened by the tool is saved and closed while preserving the previous scene. No Play Mode tests are automated; manually check initial grip, balloon lift, release input, camera framing and whiteout.
